Running your own server

Everything on elysium.cards works without any of this. Your own server is for a table that wants to stay private, play on a LAN with no internet, or run a tournament behind a locked door. It is the same software: one file, no dependencies, and once it runs your players create rooms and join exactly as they do on the public table.

Do you need this?

Probably not. elysium.cards runs a public table around the clock: open it, Create game, share the room name, play. Nothing to install for anyone. Read on only if one of these is you.

  • A LAN with no internet — a club night, a cabin, a hall with bad Wi-Fi. The server runs on one laptop; everyone else opens its address.
  • A closed circle that would rather not sit on a public server at all.
  • A tournament organiser who wants a server password (a locked door for the whole server), a referee key that decides who may create rooms, and rooms that never share a list with strangers.
  • Someone who likes to own their tools — the client and the server are two files you can read, keep and run for as long as you like.

What you get, and what you need

The Elysium server is one file, elysium-server.js, with no dependencies at all — just Node.js. It holds the rooms, keeps every hidden pile (library, crypt and hand never leave it), relays the table, and also serves the client: anyone opening the server's address in a browser gets the game immediately, always in the right version. Nobody at the table needs a copy of anything.

The .js twins carry the same data for a client opened as a local file, which cannot fetch .json files; the server never needs them.
Where the files are. Everything lives on GitHub at github.com/dtagent2000/VTES-Elysium. Download the files you need and keep them together in one folder — the launchers expect to find the server beside them. Node.js itself comes from nodejs.org (the LTS version).

Setting up the server

One person at the table runs the server. Five minutes the first time, thirty seconds every time after.

  1. Install Node.js (once). Go to nodejs.org, download the LTS version and run the installer with the defaults. On a Mac brew install node works too; on Debian/Ubuntu sudo apt install nodejs. That is the only thing you install — no database, no accounts, no packages to fetch.
  2. Download the Elysium files from GitHub into a folder of their own: the server, the client, the launchers for your system, and the bot files if your table wants bot opponents.
  3. Start the server.
    Windows — double-click start-elysium.bat.
    macOS — double-click start-elysium.command (the very first time: right-click → Open, since macOS is wary of new files; if it still refuses, open Terminal in the folder and run bash start-elysium.sh).
    Linux — in a terminal: bash start-elysium.sh (or once chmod +x start-elysium.sh, then ./start-elysium.sh).
  4. Read the banner. A window opens and prints, among other lines, Network: http://192.168.1.42:8123 — that is the address you share with the table. Leave the window open while you play; Ctrl+C shuts down and saves the rooms.
  5. Create the room. Open the address in your own browser → Create game → your name, a room name, a password if you like; the Game settings fold has the match clock, the reaction timer, board style (Classic also offers Suggested table setup: every seat's pool globe and first four crypt cards start at their own spot around the table, and Table layout: Large cards: larger cards and the lower seat row at the bottom edge, made for the discreet panel), helpers, the tournament lock and an optional referee password for the table → Create room. Then click 📋 Invite in the lobby and a ready-made invitation lands on your clipboard — paste it to your players and send the password separately.
  6. Your players join. They open your address in any browser — nothing installed — click Join game, and your room is already in the list with the server address filled in: pick it, type the password, import a deck, take a seat, Ready. Play.
Never double-click the .js file itself. Windows runs it with the ancient Windows Script Host and complains about an “Invalid character, line 1” (in your system language); on macOS and Linux it usually just opens in a text editor. The launchers exist precisely to avoid this — they find Node and start the server the right way on every system.
The startup banner — every line, what it means
LineMeaning
Localhttp://localhost:8123 — the table on your own machine. Use it to create the room yourself.
NetworkThe address on your LAN or VPN — the one you share. One line per network interface; over Tailscale one of them starts with 100.
ClientWhich HTML file is being served. (NOT FOUND!) means the client is not beside the server — move it there.
ImagesAn optional images/ folder beside the client. If it exists, card art is served from there (Settings → “Check a local images folder”); if not, players fetch art from KRCG as usual.
DataWhere the rooms and named saves are written (elysium-rooms.json, elysium-saves.json). Beside the server unless you started with --data-dir.
Door / Admin / Proxy / BindShown only when the matching option is on — a server password, a referee key (and whether room creation is restricted to it), the tunnel proxy switch, or a bind address.

Default port is 8123. If it is busy, start on another one — node elysium-server.js 8200 — and share the new address; the client appends :8123 only when a typed address has no port.

The guided launcher — passwords, referees, single-room mode

Double-click start-elysium-guided instead of the plain launcher and it asks four questions before starting; Enter on an empty line means “no” and gives you the plain server.

  1. Server password — a locked door for the whole server: browsing the room list, creating and joining all require it. Players type it under Join game → Local server → Server password (Full mode). The public table has none.
  2. Referee key (--referee-pass) — an operator credential. It is not how a judge joins a table (that is the per-room referee password the host sets under Game settings); it is what unlocks the next question, the log pull and the maintenance window (see Reference). Players never need it.
  3. Single-room server (--create-policy admin) — only someone holding the referee key may create rooms. Typed under Create game → Local server → Server referee key. For a tournament this keeps the room list exactly as the organiser laid it out.
  4. Behind cloudflared or Caddy on this machine (--trust-proxy) — say yes when the tunnel runs on the same computer as the server, so the per-player throttles see real addresses instead of everyone looking like 127.0.0.1. Harmless to leave off for a game night.

Anything the guided launcher can do, the plain command can too: node elysium-server.js [port] [clientfile] [--server-pass P] [--referee-pass P] [--create-policy admin] [--trust-proxy] [--bind ADDR] [--data-dir DIR] [--origin LIST]. A ! in a password trips the Windows shell — pick a phrase without one.

Your own copy of the client — saved decks that travel with you

The client is a single file. Double-click elysium-vtes-bord.html and it runs with no server at all: offline hotseat, bots, the Deck Lab and every tutorial work on their own. Your saved decks and downloaded card images then live with your file rather than with a website — which is why regulars keep a copy even when they mostly play on the public table. To reach a server from your own file, open Join game → Local server and type the address yourself (for the public table: the full https://elysium.cards). A local images/ folder beside your file works here too.

Bots on your own server — the bot files beside the client

The bots are not part of the server. Put elysium-bot.js and elysium-cardfx.json in the same folder as elysium-vtes-bord.html and the server serves them to every player's client. Add elysium-twd-profile.json and elysium-twd-archetypes.json beside them and the bots read your decks the way a tournament player would (a server older than srv-2.6.43 does not serve these two — the bots then play without that knowledge). Opened as a local file, the client cannot fetch .json files, so it reads their .js twins instead: elysium-cardfx.js, elysium-twd-profile.js and elysium-twd-archetypes.js — the same data, from the bot project's release. A missing or too-old bot file is refused with a message that says exactly what is wrong — the table itself is unaffected. How to seat and steer them: Help → Bots.

Beyond the LAN

The banner's address works for everyone on your network. When the table does not share a Wi-Fi, you have two good roads and one to avoid.

Tailscale — recommended

A free private network between you and your players. Encrypted, no router port opened, and the “friends around a table” trust model stays intact: nobody outside your network can even see the server.

  1. The host creates a free account at tailscale.com and installs the app.
  2. The host sends an invite link (Tailscale panel → Invite) to the players.
  3. Each player installs the app via the link and signs in. That is it — you are now on the same “LAN”.
  4. Start Elysium as usual and share your Tailscale address — the Network line that starts with 100., plus :8123.
  5. Players open http://100.x.y.z:8123 in their browsers and join as on a LAN.

Cloudflare quick tunnel — nothing for players to install

A temporary public https address that forwards to your server. Players just open the link — no app, no account. The client switches to an encrypted connection by itself when the page comes over https.

  1. Get cloudflared (once).
    Windows — download cloudflared-windows-amd64.exe from github.com/cloudflare/cloudflared/releases/latest, rename it to cloudflared.exe and put it in your Elysium folder.
    macOS — brew install cloudflared, or the release binary saved in the folder as cloudflared + chmod +x cloudflared.
    Linux — the apt/yum repo at pkg.cloudflare.com, or the release binary as above.
  2. Start the Elysium server as usual.
  3. Start the tunnel: start-cloudflare-tunnel.bat (Windows), start-cloudflare-tunnel.command (macOS, same first-time right-click → Open), bash start-cloudflare-tunnel.sh (Linux). After a few seconds the address appears in a big banner and lands on your clipboard (Windows and macOS; Linux too with xclip installed).
  4. Paste the address to your players. They open it and connect as normal.
The tunnel address is temporary and changes every time you start the tunnel. Closing the tunnel window disconnects the players, but the server and the room stay alive — start the tunnel again, share the new address, and everyone reconnects into their seats.
Set the host computer to never sleep while hosting (Windows: Settings → System → Power; macOS: System Settings → Displays/Battery). The server survives a nap; the tunnel may not — if it drops, restart the tunnel and share the new address.

Opening a router port — advised against

Technically possible, not recommended. An open port is found by scanners within hours, and a plain http table sends the room password in the clear. The server is hardened, but for game nights Tailscale is the right road and the tunnel the easy one.

Firewalls — the most common “it won't connect”

The page loads for you, but not for anyone else — that is almost always the firewall on the host machine.

  • Windows: the first time Node listens, Windows asks for access. If that dialog was dismissed: Windows Security → Firewall & network protection → Allow an app → tick Node.js for private networks. Check that your Wi-Fi is profiled as Private, not Public.
  • macOS: click Allow when asked about incoming connections for node (or add it under System Settings → Network → Firewall).
  • The wildcard: guest networks and some mesh systems run client isolation, which blocks all device-to-device traffic — switch to the main network, or use Tailscale.

The diagnosis: if the page loads at http://your-address:8123 from another device, the network and the firewall are cleared — the game travels through the same port as the page.

Running a table

Once the server runs, hosting is the same as on the public table. What follows is what a host on their own server tends to ask about.

Rooms and their lifecycle — seats, drops, hand-overs
  • Up to 6 seats per room, 10 spectators, and 50 rooms per server.
  • A dropped connection keeps the seat (marked offline). A player who loses Wi-Fi or closes the laptop drops back into their seat within seconds; even after closing the browser, joining the same room with the same name and password reclaims it — deck, board and hand restored.
  • Hosting (★) passes on to the next player if the host leaves for good. Menu → Leave seat asks a host with company whether to leave alone or close the table for everyone.
  • Rooms expire when everyone has been offline for 60 minutes; a room nobody ever sat in is cleaned up after 10 minutes, and a room with bots but no human online after 10 minutes as well (the bots live in the host's tab). While the server runs, a room otherwise lives as long as you want it to.
  • Persistence. The rooms — hidden piles, points, tokens and the encrypted hand blobs — are written to elysium-rooms.json every minute and on Ctrl+C. A restarted server restores them — board style, referee password and the bots' tempo included (srv-2.6.43; older servers forgot those, and swept a restored table within ten minutes unless somebody rejoined it) — and the players reconnect into their seats; a restored table nobody returns to closes after an hour, like any idle table. The file is ignored if it is older than 24 hours.
  • Spectators need the room password if there is one, can only chat (if the host allows it), and do not keep a room alive.
  • The match clock lives on the room; the server announces “Time is called” once when it reaches zero.
Host tools — the ★ in the room
  • Menu → Host… holds New deal, Reset table, Randomize seating, Save/Load game to file and — online — Close table…, which disconnects everyone and removes the room.
  • Every player row in the lobby and in the Table panel carries a red ✕ for the host: remove someone from the table (confirmed first). Their seat opens; a spectator can be promoted into it. If they will not take the hint, change the room password.
  • On a player's seat menu: set or step their pool, oust, un-oust, pass their turn, mute. The same tools reach a bot seat.
  • 📋 Invite puts address + room name on the clipboard; the password is deliberately never part of it. A link invite works too: your-address/?server=&room=&name= pre-fills and opens the Join dialog — one click from seated, and it never joins on its own.
Referees — a judge with the host's tools, per table

A referee is a spectator with the host's tools, for one table. The host sets a referee password under Create game → Game settings when the room is created; the judge ticks Join as referee (Full mode) and types it. From then on the referee sees the whole table without a seat and has the host's menu: pausing and passing turns, adjusting the clock, setting pool, ousting, kicking, starting, saving and loading. Rooms with a referee password show ⚖ in the room list. No password set means no referee at that table.

This is different from the server's referee key (the guided launcher's second question), which is an operator credential for the server as a whole.

Saving and loading a match — continue next week

Beyond the automatic room snapshot, the host can save a running match under a name and keep it — to continue a game next week, or to recover after a long break.

Saving

  • In a running game, click 💾 matches in the room bar (host and referee only), type a name — Friday game — and Save match.
  • A save captures every seat's deck as it stands, public board, victory points, the turn — and each player's encrypted hand. The server stores the hand only as a blob it cannot read.
  • Saves are kept per room password (the same password = the same group of friends): three per group, and a save untouched for 90 days expires.

Loading

  • Create a fresh room with the same password the match originally used — the password is how a save is found and how the seats are protected.
  • Open 💾 matches: the group's saves appear. Load drops you straight into your own seat (log in with the name you played under); the other seats wait offline.
  • Everyone else joins the new room with their own name + the same password and lands in their seat — board, deck and hand restored. A hand is restored from the blob only when the password was just typed; a plain page refresh restores it from the browser's own autosave instead.
Bots at your table — the host adds them from the lobby

With the three bot files beside the client, the host adds bots in the lobby of a Structured room (a Classic room cannot hold bots and the button says so): a name, a deck, an experience level, 🤖 Add bot. They live in the host's browser tab and connect to the room on their own sockets, so to the server and to every other player they are ordinary remote players. Everything about seating them, steering them and correcting them is in Help → Bots.

Problem reports — they land on your server

When a player at your table uses Help → Report a problem…, the report is posted to your server and appended to elysium-errors.log in the Data folder — one JSON line per report, with the last public log lines and a snapshot of the reporter's own view. No IP address is written. With a referee key set, http://your-address/client-errors.txt?key=… serves the log from a browser. Nothing is ever sent anywhere else.

Reference

The options, the protections, and the snags — for when you want the exact answer.

Command-line options

node elysium-server.js [port] [clientfile] [options] — all optional; with none, you get exactly what the plain launcher starts.

OptionEffect
8200 (first argument)Port to listen on. Default 8123.
my-client.html (second argument)Which client file to serve. Default elysium-vtes-bord.html beside the server.
--server-pass PA password for the whole server: browsing, creating and joining all require it.
--referee-pass PThe operator key (--admin-pass is an alias). Unlocks --create-policy admin, the log pull and the maintenance window; bypasses the room-creation throttle.
--create-policy adminOnly a holder of the referee key may create rooms. Default: anyone.
--trust-proxyBelieve the forwarding headers from a tunnel or reverse proxy running on the same machine, so per-player throttles see real addresses.
--bind 127.0.0.1Listen on one address only. Behind a tunnel, 127.0.0.1 makes the raw port unreachable even on your LAN.
--data-dir DIRWhere rooms, saves and the error log are written. Default: beside the server.
--origin LISTComma-separated list of page origins allowed to open a table connection (e.g. https://your-domain,null). Default: off.

The security model

Room passwords are shared phrases between friends — pick a fun phrase, never a real password. The server keeps the rest honest:

ProtectionBehaviour
Room passwordCompared in constant time and stored only as a hash — in memory and in the persistence file, never in clear text. A wrong password counts as a strike.
Lockout5 wrong passwords within 10 minutes locks that address out for 10 minutes. Behind a tunnel the strikes are counted per room instead, so one player's typo cannot lock out the whole table. Token reconnection is immune.
Rate limitingMax 80 messages per 10 seconds per connection — then disconnect. Max 16 concurrent connections per address, 400 in total.
Room creationMax 4 new rooms per address per hour (the host's own machine is exempt, as is the referee key). Of the 50 room slots, 10 are always held for rooms that have ever seated a player, so squatters cannot fill the server.
IdentityA token per browser tab (survives a refresh, dies with the tab). Name + password reclaims an offline seat; a name that is online can never be taken over.
Hidden informationLibrary, crypt and hand exist only in server memory. Face-down card names are stripped before anything is relayed; the hand is never relayed at all.
Hand escrowYour hand is encrypted in your browser with a key derived from the room password. Reconnecting, taking over a seat and loading a saved match restore your exact hand — while the server, the save file and the other players only ever see an opaque blob. Obfuscation-grade, not an audited cipher.
SanitisationEvery field passing through the server is cleaned and clamped (lengths, ranges, control characters); angle brackets are stripped from names on the server, on top of the client escaping everything it renders.
Crash isolationEvery message is handled in a guarded context; one malformed message cannot take the server down or drop the rooms.
Version checkClient and server compare their version on join and warn when the major.minor differ — the moment to fetch the matching files from GitHub.

Bring your own server

The client and the server talk over an open, documented contract — ELYSIUM-PROTOCOL.md on GitHub. If you want Elysium behind your own infrastructure — a matchmaking site, a tournament bracket, a permanent community server — you do not need to touch the client at all.

  • Point the client anywhere. The Server address field accepts any host, and the client file can be served from any static hosting. An https page connects with wss on 443 — put your endpoint behind any TLS proxy.
  • The contract is small on purpose: a minimal server is a relay plus three real duties — hold the hidden piles, advance the turn, store each player's encrypted hand blob. The crypto is entirely client-side; your server just keeps an opaque string.
  • Prove it with the shipped tests. The test-2a … test-2g suites run against any server that speaks the protocol — they are the conformance suite.

Tournament logic belongs around the table, not inside it: your pre-stage handles accounts, brackets and results, and Elysium stays the sandbox where the game is actually played.
